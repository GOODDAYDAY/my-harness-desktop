# i18n

## 1 这个插件解决什么问题

pi-desktop 需要支持多语言——今天中文明天英文，今天这个词明天那个词。没有 i18n 插件，文案硬编码在内核里，改文案要动内核、要发版。i18n 插件把所有用户可见文案贡献成外挂资源——改文案只改插件的 JSON 文件，内核一行不动。同时提供语言切换 UI。

## 2 设计决策

### 2.1 为什么是插件而不是内核

文案是内容——会变、会加语言、会调措辞。按 DESIGN.md §2 判据，"一年后会不会换"——会换，推出去。内核只管"有 i18n 初始化和语言切换"这个机制（在 shell 层的 `i18n-init.ts`），文案资源和语言切换 UI 是内容，推给 i18n 插件。

### 2.2 选了什么机制

同时贡献两个槽位：`languages`（48 个 JSON 资源文件，4 语言 × 12 命名空间）和 `settings`（语言切换页，`order: 999` 置底）。零权限——`i18n` 和 `config` 都是核心默认能力。零 `configFile`——语言切换走 `useUiStore` 的 `currentLocale`，不存插件配置文件。

### 2.3 和框架的分工

框架管：i18n 初始化（`i18n-init.ts` 调 `window.pi.i18n.resources()` 拿合并后的资源初始化 i18next 实例）、语言切换（`setCurrentLocale` 触发 i18next `changeLanguage`）、`SettingsSection` / `ListItem` 样式组件。插件管：贡献 48 个 JSON 资源文件 + 渲染语言切换网格。

## 3 怎么通信

### 3.1 和内核通信

语言切换不走 `usePluginContext`——直接调 `window.pi.i18n.list()` 拿可用语言列表（因为这是 i18n 插件自己管的列表，不是按 pluginId 绑定的能力）。语言切换走 `useUiStore.setCurrentLocale(locale)`——全局状态，`i18n-init.ts` 订阅它触发 i18next `changeLanguage`，React 组件自动重渲染。

### 3.2 和其他插件通信

间接通信。i18n 插件贡献的文案资源被所有插件通过 `t("key")` 消费——其他插件不需要知道文案是谁贡献的，只需要知道 key。语言切换时所有插件的 `useTranslation()` 自动响应——i18next 实例换资源，React 组件重渲染。这是"插件之间不直接通信，通过共享状态间接通信"的落地。

## 4 怎么处理

### 4.1 资源组织

48 个 JSON 文件分布在 `locales/{locale}/{namespace}.json`。12 个命名空间：`common`、`sessions`、`projects`、`settings`、`system`、`kernel`、`models`、`stats`、`plugin`（插件显示名翻译）、`theme`（主题名翻译）、`review`、`shell`。每个文件是 key-value 的扁平 JSON。

内核的 `mergeLanguageContributions` 做 key 级合并：不冲突的 key 全保留，冲突的按来源插件优先级取高。key 的 namespace 解析在合并器里——第一个 dot 前是 namespace，无 dot 走 `common`。

### 4.2 语言切换

`LanguageSettings` 组件渲染四语言卡片网格，点击切换。选中态用 radio-style 圆点表示。切换不重载——i18next 实例换资源，React 组件自动重渲染。`refreshSignal` 变化时重拉语言列表（框架刷新按钮触发）。

## 5 怎么保证

### 5.1 插件不碰 i18next

`LanguageSettings` 组件只调 `useUiStore.setCurrentLocale`——不直接调 i18next 的 `changeLanguage`。i18next 初始化和语言切换在 shell 层的 `i18n-init.ts` 里。插件碰不到 i18next 实例——守插件边界：插件是内容层，不依赖 shell 实现细节。

### 5.2 空态处理

`locales` 列表为空时（`window.pi.i18n.list()` 还没返回），网格为空。不报错——等数据来了再渲染。`refreshSignal` 变化时重拉。

## 6 QA

**Q：怎么加一个新语言？**

在 `locales/` 下加一个新目录（如 `fr/`），放 12 个 namespace JSON 文件。在 `plugin.json` 的 `contributes.languages` 里加资源声明。`collectSupportedLngs` 会自动收录。当前硬编码的兜底语言列表（zh-CN/zh-TW/en/de）不包含新语言——标注"演进"，应该改成纯动态收集。

**Q：第三方插件怎么贡献自己的文案？**

在第三方插件的 `plugin.json` 的 `contributes.languages` 里声明 JSON 资源文件。文件格式和 i18n 插件一致——namespace + key-value。内核的 `mergeLanguageContributions` 会自动合并，冲突时按优先级取高。

**Q：key 冲突时谁赢？**

按来源插件优先级：project > user > installed > builtin。同优先级先处理者胜。i18n 插件是 builtin，优先级最低——第三方插件可以覆盖它的任何 key。
