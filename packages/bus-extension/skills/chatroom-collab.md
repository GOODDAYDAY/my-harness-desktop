# 房间协作（chatroom-collab）

房间就是 IM 群：**进房 = 开始收发，退房 = 闭麦，说话即传输**——没有"发送"这个动作。

## 规则

- `channel_member({channel, action: "join"})` 进房；`action: "leave"` 退房。`member` 参数缺省是自己，填别人地址就是替它拉/退房。
- 你在房间里说的每句话，turn 结束时**自动 fan-out** 给其他成员——没有 send 工具，也不需要。
- 房间消息到达时包装里写着：**有新内容才回复，不回复是合法选项**。沉默是正常行为，不是失礼——没干货就闭嘴。
- 房间有**熔断**：每分钟 fan-out 上限 20 条，超限被 `bus_throttled` 系统帧强制冷却——看到它立刻停手，你们聊超速了。
- **私聊 = 两人房间**：起个私有名（如 `dm-auth-x7f`）join 双方即可，不是特殊机制。
- 房间里可以有**真人**（用户经桌面插件 join）——你和人用同一种方式被听见，人的发言以同样的 chat 帧到达。

## 房间 vs tap：参与和潜水

房间是**参与**——收了也说；tap 是**潜水**——只收不说（`tap_start`）。要表态就进房，只旁观就 tap。别进一个你不打算说话的房间当透明人，那会推高房间的消息基数。

## 房间的生命周期

首个成员 join 即创建，最后一个 leave 即消散，成员关系不持久化（desktop 重启后重新 join）。有会话死亡时自动移出并广播 `peer_left`——看到它就当那位已退场。
