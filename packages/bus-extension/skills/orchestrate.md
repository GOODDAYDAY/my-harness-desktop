# 多会话编排（orchestrate）

Session Bus 是会话间的 IM 系统：每个会话是一个用户，房间是渠道，成员关系设好之后**说话即传输**。你是编排方——拓扑由你的推理决定，总线只给能力，不预设模式。

## 标准工作流

1. **侦察一轮**：`bus_status` 拿全景——谁在跑、有哪些房间和成员、我有哪些 tap。规划之前先查，别盲派。
2. **分发一轮**：每个工人一个 `session_create({task, watch: true})`，同一轮里并行多个调用就是并行 fan-out。工人之间要互通就加 `channels: ["房间名"]`——落地即同房，不需要第二轮拉房。
3. **等结果，不看中间流**：`watch: true` 的工人完成时你收到 `session_done` 帧，含**最终完整输出**（超长截断头 1/4 尾 3/4，附 session 文件路径可取全文）。中间过程不该进你的上下文——那是 token 税；人想看过程，开那个会话的 timeline 看。
4. **汇总决策**：结果齐了你决定——合并、继续派下一轮、向用户汇报。

## 拆分原则

- 子任务**自足**：子会话是独立进程、独立上下文，不继承你的对话历史。背景、约束、验收标准全部写进 task，少一句它就得猜。
- **接口先行**：多个工人碰同一代码时，在各自 task 里钉死"你只改 X，接口签名不许动"——比事后收拾冲突便宜得多。
- **受限委托**：信任度低时给 `toolConfig`（只读分析型 `{enabledToolIds:["read","bash"]}`，显式空数组 = 全禁）。

详细模式见四个专项 skill：delegate-task（单委托）、parallel-fanout（并行分发）、supervise-worker（监督者）、chatroom-collab（房间协作语义）。
